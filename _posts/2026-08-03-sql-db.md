# 📊 sql-db 미션 심층 기술 딥다이브

## 💡 1. 미션 개요 및 배경

데이터베이스 설계 시 무결성(Integrity)이 파괴되면 이상 현상(Anomalies)이 발생하여 데이터 조작 시 데이터가 손상됩니다.

**`sql-db`** 미션에서는 도서 관리 시스템을 주제로 제3정규형(3NF) 표준 테이블 스키마를 수립하고, ORM의 도움 없이 순수 SQL 쿼리만으로 복잡한 집계, 다중 JOIN, 윈도우 함수(`ROW_NUMBER`, `RANK`)가 포함된 **16선 분석 쿼리**를 작성 및 실증했습니다.

---

## ⚡ 2. 핵심 기술 쟁점 & 트레이드오프

```text
[ Categories ] ──1:N──> [ Books ] <──1:N── [ Borrowers ]
                           │
                          1:N
                           ▼
                    [ Transactions ]
```

### 쟁점 1: 외래키(FK) 참조 무결성 삭제 정책 (`RESTRICT` vs `CASCADE`)

- **`CASCADE`**: 부모 도서 삭제 시 대출 기록까지 삭제되어 과거 결제/대출 이력 손실 위험.
- **`RESTRICT`**: 대출 기록이 남아있는 도서는 부모 데이터 삭제를 금지하여 데이터 무결성 보존.

## 🛠️ 3. 소스코드 핵심 하이라이트

### 3.1 정규화 스키마 정의 (`schema.sql`)

```sql
CREATE TABLE IF NOT EXISTS Books (
    book_id INTEGER PRIMARY KEY AUTOINCREMENT,
    title VARCHAR(100) NOT NULL,
    author VARCHAR(50) NOT NULL,
    category_id INTEGER,
    published_year INT,
    status VARCHAR(20) DEFAULT 'AVAILABLE',
    FOREIGN KEY (category_id) REFERENCES Categories(category_id) ON DELETE RESTRICT
);

CREATE TABLE IF NOT EXISTS Transactions (
    tx_id INTEGER PRIMARY KEY AUTOINCREMENT,
    book_id INTEGER NOT NULL,
    borrower_id INTEGER NOT NULL,
    borrow_date DATE NOT NULL,
    return_date DATE,
    FOREIGN KEY (book_id) REFERENCES Books(book_id),
    FOREIGN KEY (borrower_id) REFERENCES Borrowers(borrower_id)
);
```

### 3.2 윈도우 함수 기반 카테고리별 대출 순위 쿼리 (`queries.sql`)

```sql
SELECT 
    c.category_name,
    b.title,
    COUNT(t.tx_id) AS borrow_count,
    DENSE_RANK() OVER (PARTITION BY c.category_id ORDER BY COUNT(t.tx_id) DESC) as category_rank
FROM Books b
JOIN Categories c ON b.category_id = c.category_id
LEFT JOIN Transactions t ON b.book_id = t.book_id
GROUP BY b.book_id
HAVING borrow_count > 0;
```
