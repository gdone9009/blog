클라우드 서버(EC2)를 만들 때 그냥 기본 Default VPC에 퍼블릭 IP를 붙여서 띄우고 계신가요? 😱  
인터넷 세상에는 24시간 내내 봇(Bot)과 해커들이 전 세계 모든 IP의 22번 포트(SSH)를 무차별 스캔하고 있습니다!

이번 **`cloud-infra-aws`** 미션에서는 퍼블릭 클라우드 AWS 상에 **VPC(Virtual Private Cloud) 기반의 사설 격리 네트워크**를 밑바닥부터 직접 설계하고 엔터프라이즈급 인프라 보안 경계를 구축해 보았습니다. 🛡️

---

### 🏗️ 네트워크 아키텍처 설계도

우리가 구축한 사설망의 기본 구조는 다음과 같습니다:

1. **VPC (`10.0.0.0/16`)**: 외부 인터넷과 완전히 격리된 나만의 가상 네트워크 공간
2. **Public Subnet (`10.0.1.0/24`)**: 외부 웹 트래픽을 수용하기 위한 서브넷
3. **Internet Gateway (IGW)**: 서브넷과 인터넷 외부 세상을 이어주는 대문
4. **Route Table (라우팅 테이블)**: `0.0.0.0/0` 트래픽을 IGW로 전달하도록 라우팅 패킷 파이프라인 통제
5. **Security Group (보안 그룹)**: 최전방 인바운드 방화벽

---

### 🔐 최소 권한 원칙 (Principle of Least Privilege) 적용

보안에서 가장 중요한 법칙은 **"필요한 최소한의 문만 열어둔다"** 입니다.

* **IAM 정책**: 모든 권한(`*:*`) 대신 EC2 조작 및 VPC 조회 권한만 주입
* **보안 그룹 (Security Group)**:
  - HTTP 80 포트: 전 세계 웹 사용자 수용 (`0.0.0.0/0`)
  - SSH 22 포트: 오직 내 개발PC의 IP 주소만 화이트리스트 지정 (`My-Home-IP/32`)

---

### 💥 트러블슈팅 경험: "EC2를 만들었는데 외부에서 접속이 안 돼요!"

인프라를 다 구축하고 EC2에 접속하려는데 타임아웃 오류가 발생했습니다.  
원인을 추적해 보니 라우팅 테이블(Route Table)과 인터넷 게이트웨이(IGW) 연결을 빼먹은 것이 원인이었습니다!

1. Subnet 생성 ➡️ OK
2. EC2 생성 ➡️ OK
3. **Route Table에 `0.0.0.0/0 -> igw-xxxx` 라우팅 경로 추가! ➡️ 해결!**

이 경험을 통해 네트워크 패킷이 전달되는 흐름(Packet Flow)을 머릿속으로 시각화할 수 있게 되었습니다. 클라우드 인프라 엔지니어링의 매력을 듬뿍 느낀 미션이었습니다! 🚀
