# 🗄️ sql-db 미션 심층 기술 딥다이브

## 💡 1. 미션 개요 및 배경

백엔드 개발 시 ORM(Object-Relational Mapping) 라이브러리에만 의존하면, 하부 데이터베이스 엔진의 테이블 조인(Join), 인덱스(Index), 참조 무결성(Foreign Key Constraints) 원리를 간과하기 쉽습니다.

**`sql-db`** 미션에서는 프레임워크 없이 순수 표준 SQL과 SQLite를 활용하여 4개 도메인 테이블의 참조 무결성을 설계하고, 고성능 분석 쿼리 16선을 작성했습니다.

---

## ⚡ 2. 핵심 기술 쟁점 (Technical Debates & Trade-offs)

### 쟁점 1: 1:N 외래키 제약조건 `RESTRICT` vs `CASCADE` 정책

```text
[ CATEGORIES ] ──(1:N)──> [ BOOKS ] ──(1:N)──> [ RENTALS ] <──(N:1)── [ MEMBERS ]
```

- 회원이 탈퇴할 때 해당 회원의 대여 기록을 `CASCADE`로 자동 삭제하면, 회사의 **과거 대여 매출 및 도서 통계 데이터가 훼손**됩니다.
- 따라서 회원 및 도서 참조 키에는 `ON DELETE RESTRICT` 제약조건을 걸어 무단 삭제를 엄격히 방지했습니다.

```sql
-- DDL 스크립트 (schema.sql)
CREATE TABLE rentals (
    rental_id INTEGER PRIMARY KEY AUTOINCREMENT,
    member_id INTEGER NOT NULL,
    book_id INTEGER NOT NULL,
    rental_date TEXT NOT NULL,
    return_date TEXT,
    FOREIGN KEY (member_id) REFERENCES members(member_id) ON DELETE RESTRICT,
    FOREIGN KEY (book_id) REFERENCES books(book_id) ON DELETE RESTRICT
);
```

---

### 쟁점 2: ORM 없이 작성하는 고성능 데이터 분석 SQL 쿼리 16선

```sql
-- 쿼리 예시: 카테고리별 대여율 순위 및 누적 대여 건수 분석 (Window Function 사용)
SELECT 
    c.category_name,
    COUNT(r.rental_id) AS total_rentals,
    DENSE_RANK() OVER (ORDER BY COUNT(r.rental_id) DESC) AS rank
FROM categories c
JOIN books b ON c.category_id = b.category_id
JOIN rentals r ON b.book_id = r.book_id
GROUP BY c.category_id
HAVING total_rentals >= 3;
```

## 📝 4. 결론 및 성과

- **참조 무결성 보장**: `ON DELETE RESTRICT`로 도메인 데이터 파손 차단
- **분석 SQL 파이프라인**: Window Function 및 JOIN 기반 16선 분석 쿼리 자동화 🚀
